## 方法（硬性执行情况）

- 归一化：所有长度同时报原始 px（注明量测图宽度）与占屏幕宽度的百分比，禁止跨分辨率直接比原始 px。
  - 渲染：图宽 390，内屏宽 370（10px 边框），百分比以 390 计（与 PhoneFrame 声明口径一致）。
  - 原图内屏宽：iphone-03/04/06 为 1020（屏内左右边界实测，如 iphone-03 在 y=1200 行：暗边框 140-160 与 1180-1200，内屏 160-1180）；iphone-05 为 920（内屏 220-1140）；iphone-01 为倾斜手持照，无单一屏宽，一律只给透视近似并标注。
  - 例外：draft 草稿卡本身是悬浮浏览器窗（超出手机屏宽），其内部比例用“占自身卡宽”比较，不用手机屏宽归一（见 G-D1 备注）。
- 字体：PIL 量字形高度，取深色核心（阈值 RGB 三通道均小于 150）第一字形（大写字母）的上下界，即 cap 高；同时报 cap/0.72 换算的估计字号（换算假设：cap 约为字号的 0.72，SF 系常见比值）；粗细只报观察档加代码 font-weight，不从像素猜精确数值。
- 颜色：PIL 取 5x5 patch 均值，坐标见量测记录，避开边缘抗锯齿；JPEG 原图 patch 含压缩噪声，通道差在 7 以内视为一致。
- 严重度：critical = 元素缺失/错位/一眼可见错误或尺寸偏差大于 25%；major = 偏差 10-25% 或颜色/纹理错误；minor = 偏差小于 10%。
- 渲染截图环境说明：渲染 PNG 在 Linux VM 产出，该环境无 SF Pro Rounded，字体回落到系统字体。因此字体宽度/换行对照含回落不确定性；cap 高对照仍有效（cap 高主要由字号决定），但换行行数差异不单独定级。
- 裁判说明：本轮未调用裁判（主裁/备选均未用）。round4 verdict 仅作引用：chat FAIL（小镇图）、draft FAIL（封面比）、briefing FAIL（页角）、detail 内屏 PASS、home PASS（组件级，非截图 1:1）。实测数据才是本审查依据，verdict 不是放行依据。

### 状态切换图标对与 morphing 可行性

本套实际存在的切换对很少，下列逐对评估；凡本套不存在的对，明确记无，不虚构。

- M1 chevron-down 对 chevron-up（detail 标题，潜在折叠态；当前代码仅静态 down，无切换逻辑）：两路径为上下镜像同形，可直接路径插值或旋转 180 度实现；结论：可行，无需重绘。
- M2 plus 对 check（home 加号钮、composer 加号 tile 对 detail 完成勾；当前为跨组件静态对，无同一位置切换逻辑）：plus 为 2 笔划（横加竖），check 为 1 折线，节点数不同，不可直接路径插值；可行方案为定制描边动画（横线收缩、竖线旋转成勾，或 stroke-dashoffset 勾画）；结论：需重绘或定制动画，不可直接插值。
- M3 ellipsis 对 x（菜单对关闭；本套无 hamburger、无 x 图标，… 钮为静态菜单入口，无关闭态）：3 圆点对 2 斜线，节点结构完全不同，不可直接插值；如未来需要，需重绘（圆点位移拉伸成线，定制动画）；结论：本套无此对，未来需重绘。
- M4 play 对 pause（播放对暂停；本套无媒体图标）：无此对；Lucide 有 play 与 pause，但本套未用；如未来需要，三角对双竖线节点不同，需重绘或定制动画。
- M5 任务圆圈空心对完成勾（TaskListCard；当前用文字 ✓ 加背景填色，非 SVG 图标）：Lucide circle 对 circle-check：圆环描边加勾描边 draw-in（stroke-dashoffset）可行；结论：需把文字 ✓ 改为 SVG 勾路径（小重绘），方可做 morphing。
- M6 云朵在线指示（圆点对弧线；home 顶栏）：非图标切换，属状态指示形态差异，不适用 morphing；用颜色或透明度过渡即可。
- M7 发送箭头（composer）：无状态对，不适用 morphing。
- 补充：Lucide 化本身需先接包（本套未装 lucide-react），接包与否、描边统一、去掌心圆点与否，均由用户定，本轮只审。
